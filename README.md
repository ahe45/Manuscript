# Manuscript · 원고지 연습장

`wongoji-sample`을 기반으로 한 로컬 원고지 편집기입니다. Node.js 24와 MariaDB를 사용합니다. 이 폴더에서 `npm start`를 실행하고 [수험생 로그인](http://127.0.0.1:4174/)을 여세요.

`npm run build:web`로 `deploy/output`에 웹 배포 폴더를 생성합니다. 설치·운영 절차는 [외부 접속용 웹 배포](deploy/README.md)와 [Windows 오프라인 설치본](installer/README.md)을 참고하세요.

Windows 운영 서버에서는 Git으로 복제한 뒤 `start.bat`으로 처음 설정하고 실행합니다. 서버를 종료한 뒤 `update.bat`으로 업데이트할 수 있습니다. [Windows 운영 절차](deploy/README.md#windows에서-git-복제본-운영)

수험번호, 이름, 생년월일을 입력하면 `/manuscript`에서 원고지를 엽니다. 입력한 정보가 같은 원고를 다시 열 때 기준이 됩니다. 서버 PC의 수험생 로그인 화면에서 **관리자**를 누르고 비밀번호 `1234`를 입력하면 **원고지 설정**과 **답안지 다운로드** 메뉴가 열립니다. 답안지 다운로드에서는 수험생별 개별 PDF를 담은 ZIP 또는 병합 PDF를 받을 수 있습니다. **전체 답안지 다운로드**에서는 모든 수험생의 문항별 PDF 또는 수험생별 병합 PDF를 하나의 ZIP으로 받을 수 있습니다. **로그아웃**을 누르거나 서버를 다시 시작하면 다음 접속 때 로그인합니다.

같은 네트워크의 다른 기기에서 접속하도록 설정하려면 `.env`의 `LAN_HOST`에 서버 PC의 사설 IPv4 주소를, `LAN_SUBNET`에 허용할 네트워크를 넣고 서버를 다시 시작하세요. 실행할 때 표시되는 네트워크 주소로 원고지를 열 수 있습니다. 설정을 변경할 때는 서버 PC의 [수험생 로그인](http://127.0.0.1:4174/login) 화면을 사용하세요.

- 칸을 클릭하거나 터치하면 해당 위치에서 입력합니다. 마우스 드래그나 Shift와 방향키로 범위를 선택할 수 있습니다.
- 초기 설정은 한 행에 40칸, 최대 470칸입니다. 마지막 행은 30칸만 표시되어 전체가 470칸입니다. 제한이 없으면 10행으로 시작하고, 행이 더 필요하면 아래로 이어집니다.
- 원고지 오른쪽에는 두 행마다 해당 위치까지의 누적 칸 수가 표시됩니다.
- 한글 한 음절과 영문 대문자는 한 칸씩 배치합니다. 연속된 숫자와 연속된 영문 소문자는 각각 두 자씩 한 칸에 들어갑니다. 새 문단은 첫 칸을 비우고, 줄 끝에서 이어지는 띄어쓰기는 다음 행의 첫 칸을 차지하지 않습니다.
- 기본 배율은 화면 너비에 맞춘 100%입니다. 상단의 −와 + 버튼 또는 배율 드롭다운으로 원고지를 축소하거나 확대할 수 있습니다. + 오른쪽의 화면 맞춤 아이콘을 누르면 100%로 돌아갑니다. 확대하면 원고지를 좌우로 스크롤할 수 있으며, 툴바는 아래로 스크롤해도 상단에 표시됩니다.
- 입력이 1초 동안 없으면 원고가 MariaDB에 자동 저장됩니다. 문항을 옮기거나 로그아웃할 때는 최신 원고가 저장된 뒤 이동합니다. 페이지를 다시 열면 마지막으로 저장한 원고가 표시됩니다.
- 원고지 상단의 **다운로드**에서 현재 문항, 전체(개별), 전체(병합)를 선택할 수 있습니다. 전체 다운로드에는 미작성 문항도 포함합니다. 개별 PDF는 `수험번호_문항명.pdf`로, 전체(개별) ZIP은 `수험번호.zip`으로, 병합 PDF는 `수험번호.pdf`로 저장합니다. PDF는 A3 세로입니다. 로컬 개발과 Windows 설치본은 PC에 설치된 Google Chrome을, 웹 배포는 Playwright Chromium을 사용합니다.

## 양식 설정

설정 화면에서 한 행을 5~40칸으로 설정하고, 문항마다 이름과 최대 사용 칸 수를 1~10,000칸으로 설정할 수 있습니다. 기존 문항에는 종전 공통 한도가 적용되며, 문항의 글자 수를 비우면 제한이 없습니다. 빈 원고는 0칸이며, 처음부터 마지막으로 사용한 칸까지 셉니다. 들여쓰기와 문단 사이의 빈칸은 포함하고, 끝에 덧붙인 빈 줄은 제외합니다. 한 칸에 넣은 숫자 두 자나 문장부호는 1칸으로 셉니다. 한도를 넘기는 붙여넣기는 전체를 취소합니다.

원고지 제목도 설정에서 바꿀 수 있습니다. 저장한 제목은 편집기 상단과 브라우저 탭에 표시됩니다. 설정은 원고와 함께 MariaDB에 저장되며, 새로 여는 편집기에 적용됩니다.

**수험번호 자리 수**는 스핀 버튼으로 1~32자리 사이에서 선택할 수 있습니다. 설정하면 로그인할 때 해당 자리 수의 숫자를 입력해야 합니다. 앞의 `0`도 한 자리로 셉니다. 비워 두면 자리 수 규칙이 적용되지 않습니다.

**문제 개수**를 1~20개로 정하면 문제명 입력란이 그 수만큼 나타납니다. 편집기에서 현재 문제명이 표시되며 **이전 문제**와 **다음 문제**로 이동할 수 있습니다. 이동 전에 현재 답안을 저장하고, 각 문제의 답안은 문제 번호별로 보관합니다. 기존 답안은 1번 문제에 이어집니다.

## 데이터베이스

이 PC의 `localhost:3306` 세션에 `Manuscript` DB를 구성했습니다. Windows MariaDB 설정에 따라 DB 목록에는 `manuscript`로 표시됩니다. 양식 설정은 `editor_state`에, 답안은 `candidate_drafts`에 보관됩니다. 답안의 수험번호, 이름, 생년월일은 각각 `candidate_number`, `candidate_name`, `birth_date` 컬럼으로 확인할 수 있습니다.

기존 DB에서는 관리자 권한으로 `db/schema.sql`을 다시 적용하고 서버를 재시작하세요. 이후 원고를 저장하면 최종 저장 시각이 DB에 기록되어 다시 로그인해도 표시됩니다.

다른 환경에서 구성할 때는 `npm ci`를 실행하고 MariaDB 관리자 계정으로 [`db/schema.sql`](db/schema.sql)을 실행하세요. 앱 계정에는 `editor_state`의 `SELECT`, `UPDATE`와 `candidate_drafts`의 `SELECT`, `INSERT`, `UPDATE` 권한이 필요합니다. `.env.example`을 `.env`로 복사해 연결 정보를 입력하세요.

이전 해시 구조의 답안은 `legacy_candidate_drafts`에 보관됩니다. 기존과 같은 수험 정보로 로그인하면 일치하는 답안을 새 구조로 옮깁니다. 이전 기간에는 기존 `CANDIDATE_KEY_SECRET` 값과 앱 계정의 `legacy_candidate_drafts` 조회·삭제 권한이 필요합니다.

## 문장부호 배치

- 문장부호와 특수문자는 기본적으로 한 칸에 하나씩 씁니다. 물음표와 느낌표 뒤의 공백은 입력한 만큼 표시합니다.
- 숫자에 이어지는 마침표와 쉼표는 숫자와 한 칸을 공유할 수 있습니다. 예를 들어 `3.14`는 `3.`과 `14`로, `12,000`은 `12`, `,0`, `00`으로 배치합니다.
- 마침표 바로 뒤의 닫는 큰따옴표와 작은따옴표는 마침표와 한 칸을 공유합니다. 여는 따옴표는 별도의 칸에 표시합니다.
- 줄 끝 글자 뒤의 첫 공백은 다음 줄의 칸을 차지하지 않습니다. 마침표, 쉼표, 물음표, 느낌표, 쌍점, 쌍반점, 닫는 따옴표·괄호, 물결표, 퍼센트, 캐럿, 닫는 꺾쇠괄호 등은 한 칸에 두 자까지 앞줄 끝 칸에 붙입니다. 자리가 부족하면 다음 줄 첫 칸에 씁니다. 여는 따옴표·괄호가 줄 마지막 칸에 걸리면 다음 줄로 옮깁니다.
- 표시는 원고지 규칙에 맞춰 배치하며, 복사하거나 다시 편집하는 글에는 입력한 부호가 그대로 남습니다.

`npm test`로 원고지 배치, 웹 인증 설정, PDF 대기열 동작을 확인할 수 있습니다.
